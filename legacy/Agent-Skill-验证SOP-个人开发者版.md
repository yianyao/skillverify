# Agent Skill 生命周期验证 SOP · 个人开发者版

> **版本**：v1.3（2026-10-01；v1.3 SOP-07/14/26 集成 agent-skill-llm-review 技能，手工投喂保留为降级路径）
> **依据**：《Agent-Skill 生命周期验证方案》v1.3，经"个人开发者（团队 ≤2 人）可工程实现"裁剪
> **本 SOP 回答**：流程怎么走、门禁怎么判、谁来做什么、留痕存哪里、失败怎么处置。
> **配套**：操作手册（怎么做）、《人工评审检查清单》（H 类怎么勾）、《LLM 评审提示词清单》（L 类怎么问）。

---

## 1. 目的与适用范围

1.1 目的：保证个人/两人团队产出的每个 Agent Skill 在**设计、编写、测试、挂载、运行**五个阶段均按可复现的流程完成验证，低质与不安全技能不得交付上线。

1.2 适用：单人开发者或两人小团队自研、自用及小范围分发的技能。企业级多人协作、自动化运维场景不在本 SOP 范围。

1.3 裁剪声明：相对 v1.3 方案，剔除 2 类条目（运行期自动遥测 V9/V24 的自动化实现、强制 CI 流水线）、降级 8 类（详见操作手册 §1.2），其余全量保留。被剔除条目的**目标**仍以人工手段达成，不构成验证空白。**风险标注**：V7 由 [M] 自动触发降为本地执行，底线为 **git pre-commit hook 或单文件 GitHub Actions 二选一强制**（推荐 pre-commit hook），不允许两者皆无（见操作手册 §1.2）。

## 2. 角色与职责（≤2 人）

| 角色 | 职责 | 备注 |
| --- | --- | --- |
| 开发者 | D 设计说明、W 编写、E 评测执行、M 挂载、R 日志记录 | 单人时兼任全部角色 |
| 评审人（第二人，如有） | W 内容门 B 终审、E 人工复核（§7.7）、M 审计单（V13）、关键 LLM 判定的分歧裁决 | 单人时由开发者自审，**安全门 E4 与 V13 审计建议强制交叉**（哪怕隔天自审，换一份检查清单视角） |

分工纪律：内容门 B 终审项原则上不由当轮写作者即时自审——单人时至少**隔日回看**或请 LLM 预审后人工确认。

## 3. 阶段定义与出口判据

| 阶段 | 验证目标 | 出口判据（全满足才可进入下一阶段） |
| --- | --- | --- |
| **D 设计** | 取材真实、范围清晰、无命名冲突 | 《设计说明》三项齐全（V1）+ 命名预检零 FAIL（V2） |
| **W 编写** | 产出物满足全部静态 [M] 条目 + 语义条目评审通过 | 格式门 A + 安全扫描 V8 + V14/V17 零 [M] FAIL；LLM 语义评审留痕齐全（V12）；内容门 B 全 PASS |
| **E 测试** | 触发正确、产出质量有 delta 收益 | 触发门 C + 质量门 D 逐项 PASS；脚本冒烟 V6 全过；断言时机合规（V21）；**V28 写回一致性已执行并留痕**（[S] 级：FAIL 可书面放行记入验收报告，**未执行不得出口**）；`.iteration-baseline` 已记（V29） |
| **M0 挂载** | 宿主实测可发现、可加载 | V3 注册冒烟过；V4 共存冒烟过（如适用）；V23 fail-loud 过 |
| **M1 验收** | 全门复跑、依赖实测、审计留痕 | A 门 + V8 复扫 + V17 复跑零 FAIL；V5 依赖实测过；V13/V15 留档；验收报告出具 |
| **R 运行** | 问题回流迭代、正文不失控 | 运行日志持续记录；每次纠正走 V10/V26 沉淀；V27 行数漂移受控 |

## 4. 手段与分级（个人版口径）

4.1 手段映射（沿用原方案代号，个人版执行形态）：

| 代号 | 个人版执行形态 |
| --- | --- |
| S 脚本工具 | 本地小脚本套件（`check_skill.py` 等）或电子表格手算 |
| T 官方 CLI | `skills-ref validate`（可用则必跑） |
| K 专项实测 | LLM 会话 + 手动执行的端到端测试 |
| C CI 门禁 | **本地一键脚本为底线**（修订前后必跑）；GitHub Actions 单文件为可选 |
| L LLM 评审 | LLM 会话，按 V12 留痕；关键判定双评（两个独立会话或两个模型） |
| H 人工 | 检查清单逐项勾选 + 终审签认 |
| O 环境实测/遥测 | 手动环境实测（V5/V23）+ 人工运行日志（替代自动遥测） |

4.2 条目分级沿用 [M]/[S]/[P]；门禁阻断策略见 §7。

## 5. 流程步骤（SOP-01 ~ SOP-27）

> 每步格式：**动作 → 输出/留痕 → 责任人**。步骤编号可在留痕文件中直接引用。

### D 设计期

- **SOP-01** 填写《设计说明》（取材来源清单、取材计划、一句话范围、相邻技能边界）→ `.verification/design.md` → 开发者
- **SOP-02** 运行命名冲突预检（同名 FAIL；关键词重叠 >0.6 WARN）→ `name-precheck.md` → 开发者
- **SOP-03** 设计评审确认（三项齐全 + 预检通过）→ design.md 立项栏签认 → 评审人（单人则隔日自审）→ **立项**（此后才允许建目录写 SKILL.md）

### W 编写期

- **SOP-04** 编写 SKILL.md 及随包文件；行数以 **<300** 为目标、**≥240 即预警**
- **SOP-05** 运行一键静态检查 → 逐项报告存档 → 开发者；任一 [M] FAIL → 修复后重跑（回到本步）
- **SOP-06** 运行 `skills-ref validate`（可用时）；不可用时执行降级清单 → 结果留痕
- **SOP-07** 优先运行本地技能 `agent-skill-llm-review`（技能不可用时按《LLM 评审提示词清单》手工投喂），W 组逐条评审 → `llm-review-log.md` 留痕（V12）；关键判定 ⚑ 双评，分歧升级人工
- **SOP-08** 内容门 B 人工终审 → `manual-checklist.md` 存档 → 评审人
- **SOP-09** 反向测试记录核对（"删掉会错吗"逐条有记录）、执行→修订闭环记录、执行轨迹分析记录核对 → 并入 B 门留痕

### E 测试期

- **SOP-10** 建查询集（**≥12 条**，正负各半，should_trigger 标注，真实语境说明）→ `iteration-N/queries.md`
- **SOP-11** 60/40 切分并**冻结**（切分文件留存，只据训练集改 description）→ 切分文件 + 哈希
- **SOP-12** 触发评测：每条 ≥3 次新会话运行 → 记录 → 触发率统计（阈值 0.5）→ 评测记录表
- **SOP-13** 质量双跑：with/without（或旧版）各一轮，干净上下文（新会话），记录输入输出与估算成本 → `iteration-N/`
- **SOP-14** 断言：初始 2–3 条，**首轮输出后才加断言**（V21，时间戳核对）；机械断言逐条判，语义断言走提示词 E-04（可由 agent-skill-llm-review 技能执行；PASS 必附证据）→ grading.json（`text/passed/evidence` + `summary`）；**description 选定版本写回 frontmatter 后核对落盘一致（V28：文本 diff 或哈希比对），核对结果留痕**
- **SOP-15** 模式审查：恒过/恒挂/高方差断言标记；>3× 均值离群项标出 → 轨迹诊断（提示词 E-10）→ 审查记录
- **SOP-16** 脚本冒烟 V6：每脚本 `--help`/缺参/dry-run 三项 + §8.3 动态项 → 冒烟记录
- **SOP-17** 人工复核 §7.7：逐用例对照产出与评分，具体可行动反馈落盘 `feedback.json`；**空反馈 = 通过** → 评审人
- **SOP-18** 迭代循环：三路信号 → LLM 建议（E-09）→ 人工应用 → **新 iteration-N+1 目录**（不覆盖历史，V25）重跑；改进后过冷却期跑 5–10 条新查询泛化终测
- **SOP-19** 触发门 C + 质量门 D 验收 → 检查清单 E 部分签认；**改 description 后必须重跑 SOP-12，改正文重跑 SOP-13 受影响子集，改脚本重跑 SOP-16**（V7 个人版回归规则，详见 §8）→ 记 `.iteration-baseline`（V29）

### M0 挂载期

- **SOP-20** 挂载并执行三项冒烟：V3 注册可见、V4 共存不串扰（如适用）、V23 fail-loud 注入测试（临时副本注入非法 frontmatter，宿主须报错）→ 冒烟记录 → 开发者

### M1 验收期

- **SOP-21** 终检：复跑 A 门 + V8 安全扫描 + V17 预算门 → 全零 [M] FAIL
- **SOP-22** 依赖实测 V5：目标宿主实测运行器版本、网络可达、运行时版本与 compatibility 一致 → 实测记录
- **SOP-23** 审计与许可：V13 审计执行单（挂载第三方技能/素材时必做）+ V15 许可核对 → `audit-sheet.md` → 评审人
- **SOP-24** 出具《验收报告》：全门结论 + [S] 级放行理由 + V27 豁免留档（如有）→ `acceptance-report.md` → **交付**

### R 运行期

- **SOP-25** 每次使用后追加运行日志（触发正确性/脚本失败/成本异常/异常观察）→ `run-log.md`
- **SOP-26** 每周回顾：模式化问题 → 纠错沉淀 V10（LLM 归纳 R-01，可由 agent-skill-llm-review 技能执行 + 人工拍板"值得写入"）→ V26 隔离判定（累积型内容入 Gotchas/references，不堆正文）
- **SOP-27** 回流：沉淀涉及正文修改 → 触发 §8 回归规则重跑对应门 → V27 行数漂移检查（≥240 预警拆分，≥300 强制拆分）

## 6. 留痕要求（V12 个人版）

6.1 **LLM 评审留痕**：`llm-review-log.md` 每条记录——日期 | 提示词编号 | 模型名+版本 | 输出证据（引用/结论摘要）| 判定 | 是否双评。

6.2 **双评规则**：标注 ⚑ 的关键判定必须两个独立会话或两个不同模型分别判定，范围与《LLM 评审提示词清单》速查表**完全一致**：**W-02（description 触发质量）、W-04（渐进式披露）、W-05（取材真实性）、W-08（破坏性防护）、W-15（安全语义审计）、E-04（语义断言评分）、E-06（盲评）、R-02（增长性内容隔离）**；评分不一致 → 升级人工裁决并记录裁决理由。两份文档如有出入，以 LLM 清单的 ⚑ 标注为准。

6.3 **人工留痕**：检查清单填写结果存档 `manual-checklist.md`（每轮快照，不覆盖）。

6.4 **测试留痕**：`iteration-N/` 目录含 queries、切分、评测记录、grading.json、timing（估算）、feedback.json；每轮验收后记 `.iteration-baseline`（V29），任何后续操作不得覆盖历史 iteration 目录。

## 7. 门禁阻断策略

**机械门定义**：由 S/T 判定的 [M] 级检查项（个人版 C 并入本地脚本执行；启用 GitHub Actions 时属 C，同属机械门）。L/H 判定的 [M] 级条目走内容门评审/人工裁决流程，不属机械门。

| 失败情形 | 处置 |
| --- | --- |
| 任一 [M] 级机械门（格式门 A、V8 安全扫描、V14、V17 预算门）FAIL | **阻断**，不得进入下一阶段；修复后重跑 |
| 触发门 C、质量门 D 任一 [M] 级 FAIL | **阻断**，不得交付 |
| 安全门 E4 任一 [M] 级 FAIL | **无条件阻断** |
| [S] 级失败 | 告警 + 书面说明理由后放行，理由记入验收报告 |
| [P] 级失败 | 仅记录，不阻断 |

个人版补充纪律：单人复核安全项（E4、V8、V13）时，**不得**因赶进度自行放行 [M] 级失败；确有争议时搁置 24 小时后复审。

## 8. 变更与回归规则（V7 个人版）

任何修订前后必跑 `check_skill.py`（底线），并按变更影响面追加：

| 变更内容 | 必须重跑 |
| --- | --- |
| frontmatter description | 触发评测（SOP-12，训练集快跑 + 验证集） |
| SKILL.md 正文 | 质量双跑受影响用例子集（SOP-13） |
| scripts/ 任意脚本 | 脚本冒烟 V6 + §8.3 动态项（SOP-16） |
| references/、assets/ | §4.1.10 存在性 + 触发条件核对（静态检查覆盖） |
| 运行期纠错沉淀回流（SOP-26/27） | 静态检查 + 行数漂移检查；改正文再按上行追加 |
| 每轮验收完成 | 记 `.iteration-baseline`，防止历史结果被覆盖（V29） |

## 9. 异常处理

9.1 **门禁 FAIL**：按 §7 处置；修复后从失败步骤重跑，不跳步。

9.2 **V27 超行**：≥240 行预警即启动拆分（人工 + LLM 辅助，外移到 references/，写明加载触发条件，保持一层引用）；拆分后必须**显式告知用户**外移文件清单与各文件加载条件，并复跑格式门。≥300 行强制拆分。例外：超行内容全部为每次运行必需的核心指令、确无可外移项 → H 裁决豁免，**留档三项：豁免理由 + 行数证据 + 无可外移项论证**，记入验收报告。

9.3 **运行期疑似安全事件**（日志中记录到异常外部请求/非预期提权/secret 泄露迹象）：立即停用技能 → 按 V13 重新出审计单 → 处置结论留档。

9.4 **skills-ref 不可用**：执行《操作手册》附录 B 降级清单并留痕；降级期间 V17 预算门与安全扫描为最低不可省略项。
