# Weekly Report Archiver（周报自动归档）

## Overview

将散落的团队周报（文件或粘贴的文本）按统一结构自动归档，并生成周索引与周摘要，使团队周报可检索、可追溯。

## 核心概念

- **归档库根目录**（默认 `weekly-reports/`，可由用户指定）：所有周报的唯一存放处。
- **归档周期**：按 ISO 周编号组织，目录形如 `weekly-reports/2026/W40/`。
- **文件命名**：`{姓名}_周报_{YYYY-MM-DD}.md`，其中日期为该周报覆盖周期的截止日（通常为周五）。
- 详细目录结构与命名规范见 `references/conventions.md`，首次建库时向用户展示并确认。

## 工作流

### 1. 判断任务类型

- 归档新周报 → 走步骤 2-4
- 生成某周索引/摘要 → 走步骤 5
- 查询历史周报 → 按目录结构直接定位，缺失时如实告知
- 初始化归档库 → 创建目录骨架 + 复制 `assets/report_template.md` 为团队模板

### 2. 收集与解析

- 输入可能是：文件路径（md/docx/txt/pdf）、粘贴的文本、聊天记录。
- 解析出：姓名、覆盖周期（日期或"本周"）、正文内容。
- 信息不全时先向用户确认，不要猜测姓名或周期。

### 3. 规范化与落盘

- 将内容套入统一模板结构（本周完成 / 下周计划 / 风险与需协调事项），保留原文关键信息，不做删减。
- 计算目标 ISO 周，写入 `weekly-reports/{年}/W{周数}/{姓名}_周报_{截止日}.md`。
- 同一人同周期已存在归档时：默认覆盖为新版本，并保留旧版为 `{原文件名}.bak.{当日日期}`；若用户要求追加则改为合并。

### 4. 归档脚本

批量归档（≥3 个文件）时优先执行脚本，减少逐个手写：

```bash
python scripts/archive_reports.py <源目录或文件...> --root weekly-reports [--week 2026-W40] [--author 姓名]
```

- 无法从文件名/内容推断作者或周期时，脚本会跳过并列出待确认项，此时人工补齐后重跑。
- 脚本执行后必须核对输出摘要，处理 skipped 项。

### 5. 生成周索引与摘要

每周归档完成后，在该周目录生成：

- `INDEX.md`：本周所有周报列表（姓名、文件、一句话主题）。
- `DIGEST.md`：跨人摘要，按"整体进展 / 风险与阻塞 / 下周重点"三节汇总，仅聚合不虚构，无法概括的原样引用。

## 约束

- 不修改已归档周报的正文语义，只做格式规范化。
- 缺失周报仅提示，不代写。
- 所有路径变更（改根目录、改命名规则）须先与用户确认。
