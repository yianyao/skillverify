# Agent-Skill LLM Review 使用说明书（新版）

> 一句话介绍：这个技能帮你**用大语言模型给另一个 Agent Skill 做评审**——该跑哪些检查、怎么跑、怎么记录、怎么汇总，它都带你走一遍。

---

## 1. 这个技能是干什么的？

假设你写好（或改好）了一个 Agent Skill，想知道它"过不过关"。这个技能会：

1. **看进度**：检查你的技能目录，判断现在处于哪个阶段，建议你该跑哪些评审；
2. **发任务**：把对应的评审提示词一条条投喂给模型，收集 PASS / FAIL 判定；
3. **记台账**：每条评审结果立刻写入留痕文件，做到有据可查；
4. **出报告**：最后汇总所有判定，列出需要你**人工拍板**的事项。

## 2. 它不能干什么？（重要，先看这个）

| 它不做 | 原因 |
| --- | --- |
| 不替代脚本机械检查（check_skill.py） | 那是另一类检查，各管各的 |
| 不替代人工终审 | 模型判定只是建议，签字权在人 |
| 不替代真实运行测试 | 动态实测要另外做 |
| 不在一个会话里跑"双评" | 同一会话跑两遍不算双评，必须两个会话或两个模型 |
| 不修改被评审的技能文件 | 评审者不碰被评审对象 |

## 3. 四个阶段是什么意思？

技能的生命周期分四个阶段，每个阶段要跑的评审提示词不同：

| 阶段 | 含义 | 必跑项 | 需要双评的项 |
| --- | --- | --- | --- |
| D 设计期 | 还在构思、收集材料 | D-01（可选，仅提炼材料） | 无 |
| W 编写期 | 正在写 SKILL.md / 脚本 | W-01 ~ W-16 全部 | W-02、W-04、W-05、W-08、W-15 |
| E 测试期 | 在做查询集评审、断言评分、盲评等 | E-01 ~ E-10（按实际测试项） | E-04、E-06 |
| R 运行期 | 投入使用后的纠错归纳、增长内容判定 | R-01、R-02 | R-02 |

**不用背这张表**——脚本会自动告诉你当前该跑哪些（见下一步）。

## 4. 标准使用流程（照着做即可）

前提：目标技能目录下应已有 `.verification/` 留痕目录。

### 第 1 步：检测当前阶段

```bash
python scripts/detect_stage.py <你的技能目录>
```

它会输出：目前哪些阶段产物存在、**建议**你跑哪些提示词组。
注意：这只是"建议"，不等于"该阶段已完成"。完成与否要看出口判据 + 人工签认。

### 第 2 步：逐条执行评审提示词

按脚本建议，读取对应的提示词文件，一条条投喂执行：

- 设计期材料提炼 → `references/d-prompts.md`（D-01）
- 编写期语义评审 → `references/w-prompts.md`（W-01 ~ W-16）
- 测试期（断言评分 / 盲评 / 轨迹诊断）→ `references/e-prompts.md`（E-01 ~ E-10）
- 运行期（纠错归纳 / 增长内容隔离）→ `references/r-prompts.md`（R-01 / R-02）

每条判定必须**附证据引用**（引用原文哪一句、哪个文件），不能光给个 FAIL。

### 第 3 步：遇到"双评"项怎么办？

带 ⚑ 的 8 项（W-02 / W-04 / W-05 / W-08 / W-15 / E-04 / E-06 / R-02）**必须双评**，规则：

1. 先生成两份任务包：

```bash
python scripts/plan_dual_review.py --skill-dir <技能目录> --prompt-id W-15 \
    --inputs SKILL.md scripts/foo.py
```

盲评场景（两份输出不标来源、随机匿名）：

```bash
python scripts/plan_dual_review.py --skill-dir <技能目录> --prompt-id E-06 \
    --blind out_new.md out_old.md
```

2. **由人工**分别开两个会话（或用两个不同模型）各自投喂评审。
3. 两个结果分别留痕，标记 `--package A` 和 `--package B`。
4. 两份判定不一致 → 升级人工裁决，写明采纳哪份及理由；**两份都要留痕，不能只留赢的那份**。

盲评注意：脚本生成的 `mapping.json`（匿名对照表）只在最后汇总还原时打开，别让评委提前看到。

### 第 4 步：每完成一条，立刻留痕

不要攒批！跑完一条马上记录：

```bash
python scripts/record_review.py --skill-dir <技能目录> --prompt-id W-02 \
    --model "glm-4.7" --verdict FAIL --evidence "引用摘要" --dual 是 --package A
```

留痕字段：日期 | 提示词编号 | 模型名+版本 | 输出证据 | 判定 | 是否双评。
没有日志文件时脚本会按模板自动初始化，模板在 `assets/llm-review-log-template.md`。

### 第 5 步：收尾汇总

```bash
python scripts/summarize_reviews.py <技能目录>
```

它会输出：所有判定汇总、还缺哪些双评记录、有哪些分歧项。
最后把"人工裁决点"清单交给用户，由人拍板。

## 5. 常见坑（前人踩过的）

- **把脚本建议当完成**：产物存在只说明"到过该阶段"，不说明"做完了"。人工终审不能跳。
- **W-02 双评容易打架**：触发词质量偏主观。把两个会话的原始输出都贴进证据列，裁决时写清楚采纳依据。
- **敏感信息泄露**：投喂给外部模型之前，先过 `check_skill.py` 的 secret 扫描（V8）。扫出敏感内容就停，先上报。
- **退出码**：`detect_stage.py` 退出 0 = 检测正常完成；退出 1 = 用法错误或目录不存在。编排脚本可据此区分。

## 6. 改这个技能本身也要走评审

是的，自指要求：改它自己的 description 要过 W-02 双评，改结构要过 W-04 双评，全文重写要过 W-15 双评。

```
detect_stage.py  → 我现在该跑什么？
w/e/r/d-prompts  → 具体评审提示词在这
plan_dual_review → 生成双评任务包（含盲评）
record_review    → 跑完一条记一条
summarize_reviews→ 最后汇总 + 人工裁决清单
```
