# 双评与盲评执行规则（V12）

> 加载时机：当组织双评（⚑ 提示词）或执行盲评（E-06）时读取。

## 1. 双评（⚑ 提示词）

⚑ 权威范围（与清单 v1.2 一致）：**W-02、W-04、W-05、W-08、W-15、E-04、E-06、R-02**。

1. **独立性**：双评 = 两个独立会话或两个不同模型分别判定。用 `plan_dual_review.py` 生成 A/B 两份任务包后，**人工分别开两个全新会话**投喂；两个会话之间不得共享中间推理，只允许最终结论对比。
2. **本会话上限**：技能所在会话至多承担其中一份（A 或 B）；另一份必须由独立会话/另一模型完成。
3. **无效双评**：同一会话内跑两遍、同一会话换措辞重跑、把 A 会话结论喂给 B 会话——均不构成双评，留痕不得标"双评=是"。
4. **分别留痕**：A、B 两条记录均入 `llm-review-log.md`，模型名+版本各自如实填写，并分别带 `--package A` / `--package B`（写入证据列前缀）以便区分两个独立会话。
5. **分歧处置**：判定不一致 → 升级人工裁决；裁决记录须写明采纳哪份及理由；不得自动取其一，不得只留胜出方记录。

## 2. 盲评（E-06 专用）

1. 投喂前用 `plan_dual_review.py --blind` 匿名化并随机排序两份输出，生成匿名版本 A/B（blind-A.md / blind-B.md），与 E-06 提示词"版本 A / 版本 B"及输出 JSON 键 "A"/"B" 一致。
2. 评委不得接触版本来源信息；mapping.json 只在汇总还原时由执行方打开。
3. 评委输出结构化结论（各维度 1–5 分 + 证据引用 + prefer），两条记录分别留痕后交 `summarize_reviews.py` 汇总。
4. 盲评结论仅作为 E 阶段证据，**最终质量门 D 判定仍由人工签认**。
