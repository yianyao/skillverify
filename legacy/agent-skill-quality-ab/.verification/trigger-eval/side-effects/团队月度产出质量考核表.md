# 团队月度产出质量考核打分标准

## 一、考核维度与权重（总分 100）

| 维度 | 权重 | 评分要点 |
|------|------|----------|
| 产出质量 | 40 | 正确性（bug 率/返工率）、完整性（需求覆盖度、验收通过率）、规范性（代码/文档标准） |
| 时效交付 | 20 | 按时交付率、里程碑达成情况、延期原因是否可控 |
| 协作沟通 | 20 | 响应及时性、跨团队配合、文档/知识沉淀质量 |
| 过程与改进 | 20 | 流程规范遵守（评审、测试、发布）、主动优化与复用贡献、问题复盘质量 |

## 二、等级划分

| 等级 | 分数区间 | 说明 |
|------|----------|------|
| S | ≥ 90 | 显著超出预期，产出可作为标杆 |
| A | 80–89 | 全面达标，部分超出预期 |
| B | 70–79 | 基本达标，个别项需改进 |
| C | 60–69 | 未完全达标，需制定改进计划 |
| D | < 60 | 明显未达标，需重点辅导 |

## 四、使用说明

1. **打分依据客观化**：每项评分必须附"关键事实"（如验收通过率、bug 数、延期天数），避免主观印象分。
2. **建议评分人**：直属负责人初评 + 跨协作方互评（各占 50%），取加权平均。
3. **产出质量细项参考**：一次验收通过率（15）、线上/测试 bug 密度（15）、文档与规范符合度（10）。
4. **结果应用**：C 及以下需在次月 5 个工作日内提交改进计划并跟踪复核。
