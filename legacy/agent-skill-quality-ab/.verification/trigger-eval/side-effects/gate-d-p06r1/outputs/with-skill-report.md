# 评审报告：report-formatter 技能（Arm-A / 加载 agent-skill-quality-ab）

按 agent-skill-quality-ab 工作流执行：逐项核对 SKILL.md，每条问题给出【证据】（原文引用）、【严重度】与【修复建议】，并含清单外探测与平衡性评价。

## 一、逐条问题清单

### P1 核心脚本缺失【阻断】
- 证据：工作流第 2 步要求"调用 `python scripts/fmt.py --in report.md --out report.docx`"，但技能目录仅有 SKILL.md，`scripts/fmt.py` 不存在。
- 影响：安装即不可用，所有转换路径都依赖该脚本。
- 修复：提供 scripts/fmt.py 源码，或在 SKILL.md 中声明外部依赖及获取方式。

### P2 硬编码绝对路径【阻断】
- 证据："备份放在 `C:\Users\admin\templates\backup\` 下"。
- 影响：绑定他人用户目录，跨机必失败；且备份目录混入 templates 语义混乱。
- 修复：改为 `./backup/` 相对路径或环境变量 `REPORT_FMT_BACKUP_DIR`。

### P3 备份指令自相矛盾【阻断】
- 证据：同节相邻两条——"始终先备份原文件再转换" vs "无需备份，直接覆盖输出文件即可"。
- 影响：执行者无法确定唯一行为，违反指令唯一性原则。
- 修复：删除第二条，保留"始终先备份"，如需豁免场景单独列出条件。

### P4 版本号与变更日志不一致【警告】
- 证据：frontmatter `version: 2.0.0`，变更日志最新条目为 "v1.3 (2026-08)"。
- 影响：使用者无法判断当前版本实际能力；变更日志失去追溯力。
- 修复：补写 v2.0.0 变更条目，说明 1.3→2.0 的破坏性变更。

### P5 description 承诺超出正文覆盖【警告】
- 证据：description 写"支持模板、样式与批量处理"，但正文无模板/样式配置说明，批量模式仅见于变更日志"新增批量模式 `--batch`"。
- 影响：触发匹配会按超范围承诺召回，用户按图索骥会落空。
- 修复：补充模板/样式/批量三个小节，或将 description 收敛为"支持 docx 转换与基础选项"。

### P6 示例命令输入文件名拼写错误（清单外探测）【警告】
- 证据：示例代码块中 `python scripts/fmt.py --in repot.md --out final.docx --tpl corporate`，`repot.md` 疑为 `report.md` 之误。
- 影响：示例是用户最可能直接复制的文本，照抄即错。
- 修复：更正为 report.md；顺带说明 `--tpl corporate` 所需模板文件的存放位置。

## 二、平衡性评价（正面价值）
- 技能定位清晰：单一职责（markdown → docx/xlsx），未夹带无关能力；
- 工作流步骤简短有序，"输出目录不存在时会自动创建"这类行为说明是好实践；
- 变更日志格式规范（版本 + 日期 + 摘要），值得保留。

## 三、结论
阻断级问题 3 项（P1–P3），修复前该技能不具备发布条件；P4–P6 修复成本低，建议随下次变更一并处理。
