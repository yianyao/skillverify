# legacy —— 归档冻结（不维护）

这里存放**旧体系**的全部文件：12 份顶层文档、5 个旧技能、`tools/` 与 `.verification/` 的过程留痕。
它们在新系统建立时被整体归档，**保留作为对照与回归语料**，不是待修的工作区。

## 状态

- **冻结**：不修、不迁、不跟进。文件里的宿主绝对路径、`evals/evals.json` 的旧方言
  （顶层 `queries`）、`.verification/trigger-eval/` 的旧落点**都保持原样**——
  新系统报出这些问题正是它的功能，不是待办清单。
- **只读参考**：想了解旧体系做过什么、踩过哪些坑，看这里；
  想了解新系统怎么用，看仓库根目录的《技能编写指南.md》与《验证流程指南.md》。
- **回归语料**：`python -m tests.run_all --dogfood` 会把这里的真实技能跑一遍，
  用来验证新系统的规则**在真实世界的杂乱技能上不会假阳性**。
  因此这些文件**不要在无声无息中改动**——改了就等于把回归基准改了。
  确实需要调整语料时，请连同 dogfood 断言一起改，并在提交信息里说明原因。

## 不要在这里做的事

- 不要"顺手修好"某个旧技能让它过新系统的门禁（那会掩盖规则本身的问题，
  也会让回归语料失去价值）。
- 不要把这里的写法当模板抄进新技能（新写法见《技能编写指南.md》）。
- 不要从这里 import 任何东西（`tools/` 是旧脚本，新系统不依赖它）。

> 若要删除整个归档：git 历史里仍有全部内容（M0 提交 `dc072de`）；
> `--dogfood` 相关断言在 `legacy/` 不存在时会自动跳过，测试不会因此失败。
