## 1. 这个技能是干什么的？

一句话：**它帮你用 AI 检查你的 AI 技能写得合不合格。**

假设你写了一个"技能"（就是一份教 AI 干活的说明书，比如让 AI 帮你记账、帮你写周报）。你希望确认这份说明书：

- 写得清楚、没有歧义（**W 组**：编写期检查，16 条）；
- 设计合理、取材真实（**D 组**：设计期检查，1 条）；
- 实测有效、断言可信（**E 组**：测试期检查，10 条）；
- 用坏了之后能把教训沉淀回去（**R 组**：运行期检查，2 条）。

本技能内置了 **29 条现成的"检查提问"（提示词）**，外加 4 个小工具，帮你：

| 它能做 | 它不能做（重要！） |
|---|---|
| 自动判断你的技能走到了哪个阶段，建议该跑哪些检查 | ❌ 替代你拍板"合不合格" |
| 生成检查提示词，你复制给任意 AI 就能执行 | ❌ 替代安全扫描、人工终审等机械/人工关卡 |
| 帮你把关键检查拆成两份"考卷"，让两个 AI 独立判 | ❌ 在一个对话里自己给自己"双评" |
| 把每次检查结果记录在案（日期、模型、证据、结论） | ❌ 自动放行任何"红灯"结论 |
| 汇总所有记录，指出哪里有分歧、哪里还缺检查 | ❌ 保证你的技能"通过验证"——那要人工签认 |

**记住一句话：它是个得力的检查助手，不是裁判。裁判永远是你。**

### 1.1 怎么说话它才会"醒"（v1.3 触发词域锚定）

技能靠 description 里的关键词被 AI 认出来。**v1.3 起触发词全部加了"域锚定"**——必须同时提到"技能"这个对象，它才会响应。以下说法都能稳定唤起它：

- "帮我**评审 Agent Skill** / 评审这个技能"、"跑 **W 组语义检查**"
- "对技能产物做**盲评**（版本 A/B 对比）"、"对断言评分"
- "**诊断技能执行轨迹**"、"技能**过触发/漏触发**了，帮我查"、"**裁决 description 用词**与触发边界"、"归纳技能评审 **Gotchas**"

反过来，这些**不会**（也不应）唤起它：

- "帮我评审这篇文章/文案/简历/合同/标书"——**一般内容评审不适用**（v1.3 新增负向边界），这是它的硬边界，不是 bug。

> ⚠️ **已知局限**：抽象咨询式问法（如"帮我判一判它的触发词有没有毛病"这种不带具体对象和"评审/诊断"字样的）可能唤不起来。说得更具体（点名技能路径 + 用"评审/诊断/实测"动词）即可稳定触发。详见第 9 节 Q10。

## 2. 开始之前：你需要准备什么

### 2.1 硬性条件（缺一个都跑不起来）

| 条件 | 怎么确认 | 没有怎么办 |
|---|---|---|
| 技能已安装 | 目录 `C:\Users\yianyao\.workbuddy\skills\agent-skill-llm-review` 存在，里面有 `SKILL.md` | 找管理员或按技能安装流程装一次 |
| Python 3.10 或更高 | 在终端输入 `python --version`，显示 3.10+ 即可 | 装 Python（python.org 下载，安装时勾选 "Add to PATH"） |
| 一个待评审的技能目录 | 里面至少有一个 `SKILL.md` 文件 | 先把你的技能写出来 |

### 2.2 一个重要的目录约定

所有检查记录都存在**被评审技能**目录下的 `.verification`（注意开头有个点）文件夹里：

```
你的技能目录/
├── SKILL.md              ← 被检查的主角
├── references/           ← （如果有）
├── scripts/              ← （如果有）
└── .verification/        ← 所有检查记录都在这里（工具会自动创建）
    ├── llm-review-log.md     ← 评审日志（一张大表格）
    ├── design.md 等           ← 各阶段留痕
    └── dual-review/           ← 双评/盲评任务包
```

你不需要手动建这个文件夹，工具会自动创建。但你要知道：**想看"检查过什么、结论是什么"，就来这里翻。**

## 3. 5 分钟看懂核心概念

### 3.1 生命周期五阶段

一个技能从出生到退休经过 5 个阶段，每个阶段用一组字母表示：

```
D（设计）→ W（编写）→ E（测试）→ M（复核/审计）→ R（运行）
```

技能用的时间长了，会在 W→E→R 之间循环（改一版、测一轮、用一阵）。工具会看你的技能目录里有什么"痕迹"，猜你可能到了哪个阶段，并**建议**你跑哪组检查——注意只是建议，最终以人工确认为准。

### 3.2 ⚑ 双评：8 条最重要的检查要做两遍

有 8 条检查结论太关键，**一个 AI 说了不算**，必须让**两个独立的 AI**（两个不同对话窗口，或两个不同模型）分别判一次：

```
⚑ 双评范围：W-02、W-04、W-05、W-08、W-15、E-04、E-06、R-02
```

记不住没关系——工具会在你记录结果时自动提醒你"这条要双评"。

**铁律：同一个对话窗口里连跑两遍，不算双评。** 就像考试不能同一个人在两张卷子上抄自己。

### 3.3 留痕：每次检查都要记账

每次检查完，要往评审日志里记一行，包含 6 个字段：

```
日期 | 提示词编号 | 模型名+版本 | 输出证据（引用原文） | 判定(PASS/FAIL) | 是否双评
```

**为什么要记？** 因为"AI 说没问题"本身不算数，要能回溯是哪个模型、哪天、看到了什么证据才判的。日志就是审计凭证。

### 3.4 任务包：给"评委"的考卷

双评时，工具会把检查材料打包成 A、B 两份文件（内容相同但明确标注包编号），你分别开两个 AI 对话投喂，各收一份答案，再分别记入日志。

## 5. 完整流程实操（从零到出报告）

下面用一个假想的技能 `D:\my-skills\周报助手` 走一遍全流程。把路径换成你自己的即可。

### 第 0 步：打开终端，进入工作状态

```bash
# 设置常用变量（每次开终端先跑这两行，后面命令直接抄）
SKILL="C:/Users/yianyao/.workbuddy/skills/agent-skill-llm-review"
TARGET="D:/my-skills/周报助手"
```

> 💡 如果提示 `python` 找不到，把本机完整路径 `C:/Users/yianyao/.workbuddy/binaries/python/versions/3.13.12/python.exe` 代替 `python`。

### 第 1 步：体检——看看该跑哪些检查

```bash
python "$SKILL/scripts/detect_stage.py" "$TARGET"
```

你会看到类似输出：

```
目标技能: D:\my-skills\周报助手
.verification 目录: 不存在（可能尚未立项或未留痕）

阶段产物检测（存在=到过该阶段，不等于阶段完成）:
  [ ] D  design.md + name-precheck.md
  [ ] W  llm-review-log.md
  [ ] E  iteration-N/ 目录
  [ ] M  .iteration-baseline + acceptance-report.md
  [ ] R  run-log.md

提示词建议（仅建议，非门禁）:
  未检测到任何阶段产物。若为全新技能，先走 D 阶段：填写设计说明后再运行本脚本。
```

**怎么读**：`[x]` 表示检测到该阶段的痕迹；下面"提示词建议"列出已到阶段对应的检查组。**全新技能什么都不显示是正常的**，从 W 组全跑开始即可。

### 第 2 步：执行检查——把提示词投喂给 AI

打开 `references/` 目录下对应阶段的文件：

| 你要做的检查 | 打开这个文件 |
|---|---|
| 设计期（D 组） | `references/d-prompts.md` |
| 编写期（W 组，最常用） | `references/w-prompts.md` |
| 测试期（E 组） | `references/e-prompts.md` |
| 运行期（R 组） | `references/r-prompts.md` |

每个文件长这样：

```markdown
## W-02 触发质量（§6.1.x）⚑      ← 这是检查项的编号和标题

```text                          ← 两个 ``` 之间就是要复制的内容
你是 Agent Skill 触发评审员。评审以下 description 与触发相关设计：
……（提示词正文）
```
```

**操作**：

1. 复制某条提示词 ```text 代码块里的全部内容；
2. 粘贴到一个**新的 AI 对话**里，在后面附上你要检查的材料（比如 SKILL.md 全文）；
3. AI 会输出 `PASS/FAIL` 加证据；
4. **非 ⚑ 的条目**：直接记结果（第 3 步）；
5. **带 ⚑ 的条目**：先按第 7 节做双评，再记结果。

> 💡 **偷懒路径**：在 WorkBuddy 里直接说"用 W-02 检查这个 description"，AI 会替你完成投喂。

### 第 3 步：记账——把结果写入日志

每做完一条，立刻记录（不要攒批）：

```bash
python "$SKILL/scripts/record_review.py" \
  --skill-dir "$TARGET" \
  --prompt-id W-01 \
  --model "glm-4.7" \
  --verdict PASS \
  --evidence "W-01 判定 frontmatter 结构合规，证据：SKILL.md 第 1-5 行含 name/description"
```

执行后会打印"已写入"，并显示刚记录的那一行。

**参数逐个解释**：

| 参数 | 填什么 | 举例 |
|---|---|---|
| `--skill-dir` | 被评审技能的目录 | `D:/my-skills/周报助手` |
| `--prompt-id` | 检查项编号（必须是 D-01 / W-01~W-16 / E-01~E-10 / R-01、R-02 之一的格式） | `W-03` |
| `--model` | 哪个 AI 判的，带版本号 | `"glm-4.7"`、`"claude-x"` |
| `--verdict` | 结论，只能填 `PASS` 或 `FAIL` | `PASS` |
| `--evidence` | 证据摘要，**必须引用具体内容**，不能写"感觉没问题" | `"第 12 行明确列出触发场景"` |
| `--dual` | 是否双评：`是` / `否` / `不适用`（默认"不适用"） | `是` |
| `--package` | 双评包编号：`A` 或 `B`（双评时必填） | `A` |

**两个自动保护**：

- 如果 `--prompt-id` 是 ⚑ 条目但你没标 `--dual 是`，工具会**警告**你并提示下一步（记录仍会写入，但你要补双评）；
- 如果 `--prompt-id` 格式不对（比如写成 `W2` 或 `W-02|x`），工具直接拒绝并告诉你正确格式。

### 第 4 步：收尾汇总——看看整体什么情况

全部检查完，跑一次汇总：

```bash
python "$SKILL/scripts/summarize_reviews.py" "$TARGET"
```

输出分四段，逐段理解：

```
总记录数: 16                    ← 你一共记了几笔账
FAIL 数: 2                      ← 有几条红灯
  FAIL W-02 (dual=是, glm-4.7): [包A] description 未覆盖"导出"场景   ← 红灯明细

双评缺口（⚑ 项须 ≥2 条记录且全部 dual=是）:   ← 哪些关键检查还没做够两遍
  缺记录: R-02                  ← 完全没做
  记录不足: E-06（现 1 条；补齐第二条后才能判定是否分歧）  ← 只做了一遍

双评分歧（同编号判定不一致，须人工裁决）:     ← 两个 AI 意见不合的
  W-05: FAIL vs PASS → 升级人工裁决

提醒: 本汇总为建议输出；PASS/FAIL 最终放行由人工签认，[M] 级 FAIL 不得自动放行。
```

**你的动作**：逐条处理 FAIL 和"分歧"——分歧意味着两个 AI 说法不一，**必须由你（人）看证据后拍板采信哪边，并把理由写进验收记录**。

### 第 5 步：查账

所有记录都在 `$TARGET/.verification/llm-review-log.md`，用任何编辑器打开就是一张 Markdown 表格，随时翻阅。

## 6. 四个脚本工具详解

### 6.1 `detect_stage.py` — 阶段体检

```bash
python "$SKILL/scripts/detect_stage.py" <被评审技能目录>
```

- **做什么**：扫描 `.verification/` 里的痕迹文件，报告五阶段状态，建议应跑的检查组。
- **输出**：屏幕打印（不写任何文件）。
- **退出码**：`0` = 检测完成；`1` = 参数错误或目录不存在。
- **⚠️ 重要心态**：它说"到过 E 阶段"只代表有 E 阶段的文件，**不代表 E 阶段做完了**。完没完成以你的签认为准。

### 6.2 `record_review.py` — 记账

```bash
python "$SKILL/scripts/record_review.py" --skill-dir <目录> --prompt-id <编号> \
    --model "<模型名+版本>" --verdict PASS|FAIL --evidence "<证据摘要>" \
    [--dual 是|否|不适用] [--package A|B]
```

- **做什么**：往 `.verification/llm-review-log.md` 追加一行记录；日志不存在时自动按模板创建。
- **退出码**：`0` = 成功；`1` = 参数错误（含 prompt-id 格式不合法）；`2` = ⚑ 条目未标双评（**警告**：记录已写入，需补双评）。
- **小知识**：证据里的竖线 `|` 和换行会被自动替换成全角 `｜` 和空格，防止弄坏表格——所以你不用担心特殊字符。

### 6.3 `plan_dual_review.py` — 出考卷（双评/盲评）

双评模式（给两个 AI 各出一份卷子）：

```bash
python "$SKILL/scripts/plan_dual_review.py" \
  --skill-dir "$TARGET" \
  --prompt-id W-15 \
  --inputs "$TARGET/SKILL.md" "$TARGET/scripts/foo.py"
```

盲评模式（两份输出分不出谁是谁，让评委盲打分）：

```bash
python "$SKILL/scripts/plan_dual_review.py" \
  --skill-dir "$TARGET" \
  --prompt-id E-06 \
  --blind 新版输出.md 旧版输出.md
```

- **产出位置**：`$TARGET/.verification/dual-review/<编号>-<时间戳>/`
  - 双评：`A-task.md`、`B-task.md`
  - 盲评：`blind-A.md`、`blind-B.md`、`mapping.json`（对号密钥，**投喂评委前绝对不能给评委看**）
- **内置保护**：目标技能目录不存在会拒绝（不会乱建文件夹）；盲评两个文件相同会拒绝；双评/盲评参数二选一。

### 6.4 `summarize_reviews.py` — 汇总对账

```bash
python "$SKILL/scripts/summarize_reviews.py" <被评审技能目录>
```

- **做什么**：读评审日志，汇总总记录数、FAIL 明细、双评缺口、双评分歧。
- **退出码**：`0` = 成功；`1` = 日志不存在或格式解析失败。

## 7. 双评与盲评操作指引

### 7.1 双评（针对 ⚑ 的 8 条检查）——手把手

以 `W-15`（安全语义审计）为例：

**① 出卷**

```bash
python "$SKILL/scripts/plan_dual_review.py" \
  --skill-dir "$TARGET" --prompt-id W-15 \
  --inputs "$TARGET/SKILL.md"
```

**② 找两个"独立评委"**

- 评委 1：新开一个 AI 对话窗口（比如 WorkBuddy 新会话）；
- 评委 2：**另一个**新对话，或换一个不同的模型。
- ❌ 同一个窗口连问两遍 = 无效双评。

**③ 分发**

把 `A-task.md` 的内容完整粘贴给评委 1，`B-task.md` 粘贴给评委 2。等两份答案回来。

**④ 分别记账**

```bash
python "$SKILL/scripts/record_review.py" --skill-dir "$TARGET" \
  --prompt-id W-15 --model "glm-4.7" --verdict PASS \
  --evidence "未发现敏感信息外发" --dual 是 --package A

python "$SKILL/scripts/record_review.py" --skill-dir "$TARGET" \
  --prompt-id W-15 --model "claude-x" --verdict PASS \
  --evidence "脚本仅本地读写，无外部端点" --dual 是 --package B
```

**⑤ 看结果**

- 两个都 PASS / 都 FAIL → 结论一致，正常处理；
- 一 PASS 一 FAIL → 汇总会报"分歧"→ **你人工看两边的证据，拍板采信哪边，理由写进验收记录**。不得只留胜出方。

### 7.2 盲评（E-06 专用）——"不知道谁是谁"的对比测试

适用场景：你想知道"加了技能之后输出是不是真的变好了"，又怕先入为主。

```bash
# ① 准备两份输出：一份"用了技能"的，一份"没用技能"的
python "$SKILL/scripts/plan_dual_review.py" \
  --skill-dir "$TARGET" --prompt-id E-06 \
  --blind with_skill_output.md without_skill_output.md
```

工具会**随机**把两份文件标记为"版本 A"和"版本 B"（你也不知道哪个对应哪个），生成 `blind-A.md`、`blind-B.md` 和密钥 `mapping.json`。

**② 把 blind-A.md、blind-B.md 分别投给两个 AI（或一个 AI 按提示词里的 JSON 格式输出打分）。**

**③ 汇总打分后，才打开 mapping.json 还原"版本 A 原来是谁"。**

> ⚠️ 全程不要让评委接触 mapping.json，否则盲评作废。

## 8. 常见场景速查

**场景 A：我就想快速检查一下 description 写得好不好**
→ 在 WorkBuddy 里说："用 W-02 检查 `<技能目录>` 的 description"。单条检查，结果记入日志即可。

**场景 B：技能刚写完，第一次全面体检**
→ 跑 `detect_stage.py` 看建议 → W 组 16 条全跑（先非 ⚑ 后 ⚑）→ 每条记结果 → `summarize_reviews.py` 收尾。

**场景 C：改了一版 description，想知道有没有变好**
→ 用 `--blind` 做盲评（E-06），新旧版输出对比。

**场景 D：技能用了两周，有几个 bug 修了，想沉淀经验**
→ 跑 R 组（R-01 归纳教训、R-02 判定该写进哪里），R-02 要双评。

**场景 E：日志记乱了/记错了怎么办**
→ 直接用编辑器打开 `.verification/llm-review-log.md` 手工修改或删除错误行（工具只追加，不校改历史）。

**场景 F：技能老是"不该出手时出手"或"该出手时不出手"（v1.3 新增能力）**
→ 在 WorkBuddy 里说："诊断一下 `<技能目录>` 的触发情况，它老是误触发/叫不出来"。v1.3 起明确支持"诊断技能过触发或漏触发、裁决 description 用词与触发边界"。想要数据化结论（触发率实测），请配合 `agent-skill-trigger-eval` 技能使用。

**场景 G：我就是想让人评一篇文章/简历，它不理我**
→ 正常。v1.3 起一般内容评审是显式排除项，这技能只管"Agent Skill 的质量"。请直接让 AI 评审，不要经由本技能。

## 9. 常见问题与排错

**Q1：提示 `python: command not found` / 不是内部或外部命令**
Python 没装或不在 PATH。用完整路径代替：`C:/Users/yianyao/.workbuddy/binaries/python/versions/3.13.12/python.exe`。

**Q2：`错误: 目标技能目录不存在`**
`--skill-dir` 写错了。检查路径拼写；注意这个工具**故意不会**替你创建目录，防止路径写错时悄悄生成一堆空文件夹。

**Q3：记录时提示"⚑ 双评范围，本次记录 dual=否"，exit=2**
这不是报错，是提醒：这条检查很重要，必须两个独立 AI 分别判。按第 7.1 节流程补双评，再补一条 `--dual 是` 的记录。

**Q4：`错误: prompt-id 格式不合法`**
编号必须是"字母-两位数字"格式，如 `W-02`、`E-06`。`W2`、`W-2`、`W02` 都不行。

**Q5：summarize 说"日志中未解析到有效记录行"**
日志表格被手工编辑弄坏了（比如某行列数不对）。打开 `llm-review-log.md` 对照第 3.3 节的 6 字段格式修正。

**Q6：双评两个 AI 结论不一样，听谁的？**
都别直接听。把两份证据摆在一起，**你自己**判断谁的证据更扎实，然后：采信的那条照常记，同时把"分歧与裁决理由"写进验收记录。裁决理由缺失 = 这次双评白做。

**Q7：能不能让一个 AI 在同一个对话里既当评委 A 又当评委 B？**
不能。这是双评的底线（同会话两遍 = 自己抄自己）。留痕时也不能标"是"。

**Q8：`.verification` 文件夹能删吗？**
它是你的全部检查凭证。删了等于"审计记录清零"，技能的验证状态回到未验证。确认不再需要时才删。

**Q9：投喂材料给外部 AI 网站安全吗？**
先确认材料里没有密码、密钥、token 等敏感信息（可先跑安全扫描）。命中敏感信息就不要投喂外部服务。

**Q10：我明明在说技能评审的事，AI 却没加载这个技能（v1.3 已知局限）**
大概率是问法太"抽象咨询"——实测发现"判一判/查查根子/找找毛病"这类不带具体对象的问法不容易触发。**解法**：点名技能路径 + 用明确动词，例如"帮我评审 `D:\my-skills\周报助手` 这个技能的 description"或"诊断这个技能的过触发问题"。v1.4 已停止迭代触发词（避免引入新的误触发），此局限长期存在，随包交付。

**Q11：它会不会把我写的文章/简历也拿去"双评盲评"一套流程？**
不会。v1.3 description 有负向边界："文章、文案、简历、合同、标书等一般内容评审与盲评不适用"。如果你发现它对这类请求也响应了，那属于误触发，请记录场景并反馈维护者。

## 10. 名词小词典

| 名词 | 大白话解释 |
|---|---|
| 技能（Skill） | 一份教 AI 干活的说明书（含 SKILL.md 等文件） |
| 提示词（Prompt） | 让 AI 执行某个检查任务的完整指令文本 |
| D/W/E/M/R | 技能一生的五个阶段：设计→编写→测试→复核审计→运行 |
| W-02 这类编号 | 检查项的"准考证号"，W 组第 2 条 |
| ⚑ / 双评 | 星标 = 重要检查，必须两个独立 AI 各判一次 |
| PASS / FAIL | 检查结论：通过 / 不通过 |
| 留痕 | 把每次检查的时间、模型、证据、结论记入日志，可回溯 |
| 任务包 A/B | 给两位评委的考卷，内容相同、编号不同 |
| 盲评 | 评委不知道作品是谁写的，只按质量打分 |
| mapping.json | 盲评的"对号密钥"，事后才打开还原身份 |
| `.verification/` | 存放全部检查记录的文件夹（审计档案柜） |
| exit / 退出码 | 命令执行结果的数字代号：0=正常，非 0=有问题 |
