# Agent-Skill 验证操作总说明书（新手版）

> **本文档是什么**：把散在各处的验证操作串成一条从头到尾的路——你从"想做一个技能"开始，照着本文一步步走，就能走完设计 → 编写 → 测试 → 交付 → 运行的完整验证流程。每一步都写明：**做什么、用什么（工具或技能）、敲什么命令、怎么算过**。
> **读前只需知道**：技能（Skill）= 一个带 SKILL.md 的文件夹；本仓库 `D:\sData\specSkill\` 是所有验证工具和技能的家。
> **赶时间**：会话里直接说"**用 agent-skill-validation-suite 帮我验证 xxx 技能**"，编排技能会自动选阶段、自动调工具（见 §7）。

---

## 0. 全景图：一个技能的一生，验证跟着走

```
设计 ──► 编写 ──► 测试 ──► 挂载/交付 ──► 运行
 │        │        │          │           │
 命名预检  格式检查  触发评测    交付终检    周期体检
 安全预审  静态补检  产物校验   官方校验    纠错沉淀
          安全扫描  双跑对照   验收报告
          预算门   脚本冒烟
          官方校验  加载注入
```

三条铁律贯穿全程（详见 `README.md` §四）：
1. **每步留痕**：所有验证结果落盘到技能目录的 `.verification/` 下，报告可复查。
2. **先写后测**：评测断言必须在看到首轮真实输出之后才能写（防"照着答案出题"）。
3. **不信任自述**：触发与否、质量好坏，只认子代理实际调用记录和程序重算，不认"我觉得没问题"。

## 1. 设计期——动手写之前（防"重名撞车"）

**目的**：确认你想做的技能不会和库里的现有技能重名、定位重叠。

**执行者**：`tools/naming_precheck.py`（命名冲突预检器，检查项 V2）

```bash
cd D:\sData\specSkill
python tools/naming_precheck.py --name 你的技能名 --description "一句话描述" --library .
```

**怎么算过**：全部 PASS（退出码 0）。有同名= FAIL 必须改名；相似度告警= WARN 需人工判断定位是否实质重叠。
**配套**：这一步同时做设计评审（人工确认：取材来源真实、边界一句话说得清）——清单见 `standardSkill/Agent-Skill-人工评审检查清单.md`。想参考"官方怎么教做技能"，可加载 **skill-creator** 技能（官方内置）获取创建指引，再按本仓库规范落地。

## 2. 编写期——SKILL.md 写完每改一轮跑一次

### 2.1 一键静态检查（格式门 A）

**执行者**：`tools/check_skill.py`（格式检查权威校验器）

```bash
python tools/check_skill.py <技能目录>
# 可选：--out 报告.md 落盘；--lines N 自定义行数上限（默认 300）
```

**查什么**：frontmatter 可解析、name 规则、description 长度、目录/文件规范、引用存在、行数预算（<300 行，达 80% 即预警）等 11 组硬检查。
**怎么算过**：exit 0（10/10 全 PASS）。exit 2 = 只有警告，逐条看。

### 2.2 安全扫描（检查项 V8）

**执行者**：`tools/security_scan.py`

```bash
python tools/security_scan.py <技能目录>
```

**查什么**：密钥泄露（正则+熵检测）、不可信外部端点、交互式阻塞调用、破坏性命令无防护旗标、危险指令关键词，共六项。

### 2.3 上下文预算门（检查项 V11/V17）

**执行者**：`tools/token_budget.py`

```bash
python tools/token_budget.py <技能目录>
```

**查什么**：SKILL.md 行数/token 预算、扩展层单文件 ≤500 行，超限会阻断。

### 2.4 依赖检测（DEP-1~5）

**执行者**：`tools/dep_check.py`

```bash
python tools/dep_check.py <技能目录>
```

**查什么**：外部包是否钉版本、依赖声明是否内联在脚本头部（PEP 723 等）、是否漏报。

### 2.5 官方校验器（写完必跑一次）⭐

**执行者**：官方 CLI `agentskills validate`（即 PyPI 官方包 skills-ref 0.1.1 的命令行入口；⚠ npm 上同名的 skills-ref 是第三方占位包，勿装）

```bash
# 已装于托管环境：C:\Users\yianyao\.workbuddy\binaries\python\envs\default\Scripts\
agentskills validate <技能目录>
```

**怎么算过**：输出 `Valid skill`、退出码 0。这是 Anthropic 官方解析器，frontmatter 任何它不接受的东西它都会报错（fail-loud）。
**本地工具已集成**：`check_skill.py` 的 A1 检查项会自动探测并调用它（PATH 含上述 Scripts 目录时实检，否则 SKIP 不计警告）。

> 省事做法：§2.1–2.6 这六步，直接用编排技能跑 §7 的一键命令（`--stage write`）。

### 2.6 编写期静态补检（检查项 L-1~L-18）

**执行者**：`tools/w_static_lint.py`（验证补全工程甲档工具一）

```bash
python tools/w_static_lint.py <技能目录>
# 可选：--out 报告.md 落盘；--host 词1,词2 增补宿主专属黑名单词（L-11 用）
```

**查什么**：check_skill 不覆盖的编写期静态项 18 项——同义变体目录名（L-1）、无关文件/白名单/体积（L-2）、frontmatter 顶层键白名单（L-3）、块标量（L-4）、metadata 值类型（L-5）、allowed-tools 格式（L-6）、**引用链二层扫描**（L-7，A8 只查一层）、Gotchas 节（L-8）、templates/assets 归置（L-9）、**全包宿主路径**（L-10，A8 只查 SKILL.md）、宿主专属黑名单（L-11）、**全包 LF/无 BOM**（L-12）、.gitattributes（L-13）、i18n 混入（L-14）、代码块命令混译（L-15）、行数漂移基线比对（L-16）、笼统指引初筛（L-17）、恶意特征初筛（L-18，终判归 LLM/人工）。

**怎么算过**：exit 0；exit 2 = 有 WARN（初筛类 L-17/L-18 须人工/LLM 终判，语义条目归乙档 LL-1~LL-8 列表）。

## 3. 测试期——验证它真的"行"

### 3.1 触发评测（触发门 C）——"该触发的时候会不会触发"

**执行者**：`agent-skill-trigger-eval` 技能（实测编排）

1. 构造查询集：正例/负例各 8–10 条（规范见其 `references/queryset-spec.md`），冻结切分为训练集/验证集（60/40）。
2. 每条查询派 3 个全新子代理会话实测，只认工具调用历史。
3. 统计：`python agent-skill-trigger-eval/scripts/calc_trigger_rate.py --runs runs.json --queryset queryset.json --out 报告.md`
4. **过门线**：每条触发率 ≥0.5；只许根据训练集失败修改 description，验证集只用来选版。

### 3.2 质量双跑对照（质量门 D）——"带技能是不是真比不带强"

**执行者**：`agent-skill-quality-ab` 技能（实测编排）

- 同一任务，带技能 vs 不带技能各跑若干次（干净子代理上下文），按断言打分算增量（delta）。
- 铁律：断言必须程序重算，不信任手填 summary；增量解读 + 成本裁决归人工。

### 3.3 语义评审（W 组）——"内容写得对不对、好不好"

**执行者**：`agent-skill-llm-review` 技能（LLM 语义评审，v1.4）

- 会话里说"对 xxx 技能跑语义评审"即可。覆盖事实性、安全性语义项、双评交叉复核、盲评等，全程落盘留痕。
- 语义断言评分须附具体证据；关键判定双评（两个独立会话各评一遍再对账）。

### 3.4 脚本冒烟（检查项 V6）——技能里带的脚本能不能跑

**执行者**：`tools/smoke_runner.py`

```bash
python tools/smoke_runner.py <技能目录>
```

**查什么**：每个捆绑脚本 5 项——`--help` 内容正确、无参报错带用法、`--version`、参数错误退出码、输出限量。

### 3.5 跨宿主加载注入（检查项 V23）——"坏 frontmatter 会不会被静默吞掉"

**执行者**：`tools/inject_test.py`

```bash
python tools/inject_test.py <技能目录>
```

**查什么**：把非法 YAML/缺必填键/坏 name 三种"病毒样本"注入临时副本，官方解析器必须报错拒绝（fail-loud）；静默接受 = FAIL。原目录只读自证。

### 3.6 评测纪律三门（V21/V28/V29）

**执行者**：`tools/eval_discipline.py`

```bash
python tools/eval_discipline.py <技能目录>                 # check 模式：三项检查
python tools/eval_discipline.py --mode record --version v1.0 \
  --iteration 1 --accepted-at 2026-10-03T14:00:00 \
  --snapshot-dir <绝对路径>/iteration-1 <技能目录>          # record 模式：落基线快照
```

**查什么**：断言加入时间晚于首轮产出（V21）；description 优化写回后与选定版逐字符一致（V28）；验收基线快照防历史覆盖（V29）。⚠ `--snapshot-dir` 必须传**绝对路径**（相对路径会解析到错误位置——实测踩过的坑）。

### 3.7 评测产物校验（检查项 Q-1~Q-9）

**执行者**：`tools/eval_artifacts_check.py`（验证补全工程甲档工具二；技能有 `.verification/` 产物时跑）

```bash
python tools/eval_artifacts_check.py <技能目录>/.verification
# 可选：--out 报告.md 落盘；--queryset qs.json / --split train.json,val.json 显式指定；
#       --min-count 20 用全量口径（默认 12 个人版）
```

**查什么**：查询集 schema/条数/配比（Q-1）、切分比例 + ⊆ 全量 + frozen.sha256 哈希冻结一致（Q-2，只读冻结文件）、timing/grading/benchmark 产物 schema（Q-3/Q-4/Q-5，summary 与断言重算对账——**不吃手填**）、恒过/恒挂/摇摆清单（Q-6）、离群值 >3× 均值（Q-7）、评审留痕字段完整性（Q-8）、迭代状态对账（Q-9，INFO）。

**怎么算过**：exit 0；产物缺失=SKIP 不计警告（区别于 schema 错 FAIL）；Q-6/Q-7 为机械清单输出（WARN），处置归人工。

## 4. 交付期——发布前最后一道关

### 4.1 全门终检 + 验收报告

**执行者**：`tools/deliver_check.py`（交付物检查器 EX-1~7）+ §2/§3 全量复扫

```bash
python tools/deliver_check.py <技能目录>
```

**查什么**：SKILL.md 与 evals/evals.json 在场（EX-1）、feedback/grading 结构、license 声明与随包 LICENSE 文件（EX-4，对外发布必查）、迭代留痕与轨迹记录在场（EX-5~7）。

**验收报告**：全部跑完后写 `.verification/acceptance-report.md`（这是 deliver_check 期望的规范位置），含门次汇总、WARN 明细、待人工裁决项、报告哈希留痕。**报告落盘后复跑一次 deliver_check——EX-1 应由 WARN 转 PASS**（闭环实证）。

### 4.2 人工终审

按 `standardSkill/Agent-Skill-人工评审检查清单.md` 走纯人工项（授权最小化、用途一致性、防护终审等），出签认回执并回写留痕。

## 7. 一键编排：agent-skill-validation-suite（推荐入口）⭐

上面所有阶段不必逐个记命令——**编排技能** `agent-skill-validation-suite` 会按阶段自动选工具、自动跑、汇总判定：

| 场景 | 会话里说 | 它做什么 |
|---|---|---|
| 设计期 | "我想做个叫 xxx 的技能，先预检一下" | 调 naming_precheck（V2） |
| 编写期 | "xxx 技能写完了，验证一下" | 格式门 A + **静态补检（w_static_lint L 系）** + 安全扫描 + 预算门 + 依赖检测 + **agentskills validate（官方校验）** |
| 测试期 | "跑一下 xxx 的冒烟和注入测试" | smoke_runner（V6）+ inject_test（V23）+ eval_discipline check + **产物校验（eval_artifacts_check Q 系，有 .verification 时）** |
| 交付期 | "xxx 要交付了，跑全门验收" | 10 门全量复扫（等价验收流程） |
| 不确定阶段 | "帮我看看 xxx 现在该验什么" | auto 模式：按目录产物自动判阶段 |

也可以直接命令行调度（不进会话）：

```bash
python agent-skill-validation-suite/scripts/validate_suite.py --stage write  --skill-dir <技能目录>
python agent-skill-validation-suite/scripts/validate_suite.py --stage deliver --skill-dir <技能目录>
python agent-skill-validation-suite/scripts/validate_suite.py --stage auto   --skill-dir <技能目录>
```

**注意**：编排技能负责"调齐工具、汇总报告"，**不替代**人工终审、触发评测的子代理实测和双跑对照的现场编排——那三件事仍按 §3.1–3.3 由对应技能执行。

## 9. 出问题怎么办（速查）

| 症状 | 先看 |
|---|---|
| 工具报 FAIL 但你觉得是误报 | 对应 `.verification/` 报告里的证据行；再查 `tools/OPERATIONS.md` 异常速查表 |
| agentskills 找不到 | PATH 加 `C:\Users\yianyao\.workbuddy\binaries\python\envs\default\Scripts\`；否则 A1 走 SKIP（不计警告） |
| record 基线快照内容不对 | `--snapshot-dir` 是否绝对路径（历史踩坑：相对路径解析到设计库根） |
| 验收报告 deliver_check 仍 WARN | 报告是否落在 `.verification/acceptance-report.md` 规范位 |
| 代号看不懂 | `GLOSSARY.md` 术语总表 |
| 不知道项目整体状态 | `standardSkill/K类实现-状态卡.md` |
