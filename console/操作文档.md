## 一、启动操作台

### 1.1 一键启动（Windows）：`console/start.bat`

双击即可。脚本依次做三件事（全部自动，安装类动作先征求同意）：

1. **探测 Python 环境**：依次尝试 `python` → `py -3` → `python3` → `uv run python`
   （兼容 uv 管理的 Python）。全部找不到时提示原因，并**询问是否用 winget 安装
   Python 3.12**——同意才装；装完若当前窗口 PATH 未刷新，会提示重开窗口再跑一次。
2. **探测 skillverify 可用性**：
   - 有已安装入口（`skillverify --version` 可用）→ 桥直接用它；
   - 没有安装 → **仓库模式**（`python -m skillverify`，从仓库根直接跑，**无需安装**）；
   - 两者都不可 → 给出 `pip install skillverify` 提示。
3. **启动**：新窗口起执行桥（`serve_bridge.py`，仅监听 127.0.0.1:8742），
   然后打开 `app/index.html`——页面自动探桥，徽标变绿"桥已连接"即在线模式；
   关掉桥窗口即停止。探不到桥时页面自动降级静态模式，一切照旧。

只想核对环境不启动任何东西：`console\start.bat --check`。

### 1.2 静态模式

双击 `console/app/index.html`。断网、无服务、无 Python 环境均可完整使用；
数据是构建快照，skillverify 演进后需按 §二 重建。

### 1.3 手动启动桥（macOS / Linux / 想自己控制时）

```bash
# 开发仓库（未安装入口）：
python3 console/serve_bridge.py --tool-cmd "python3 -m skillverify"
# 已安装 skillverify 入口时：
python3 console/serve_bridge.py
```

浏览器打开 `console/app/index.html` 即可（file:// 也能探到桥）。

## 二、MAINT-01：重跑生成器（skillverify 参数面变更后）

**触发**：skillverify 合并了参数面变更（增删子命令/参数、改默认值、改 choices）。

```bash
python console/build.py                     # 重跑内省（自动读取工具的命令与参数结构）→ 重新合并 manual → 重新内联 index.html
git diff console/nodes.json                 # 人工过目参数面差异（这一步不许跳过）
python tests/test_console_consistency.py    # 守卫（重生成一致 / lint 对账 / 数据源等价）
```

- `console/nodes.json` 是入库产物，与 `console/manual/` **同一 commit** 提交；
- 机械层（内省自动拿到的命令与参数）与语义层（`console/manual/` 里人工补的说明）冲突时生成器逐条报错退出（语义层不得覆盖 argparse 已声明字段）——
  报错说明 manual 里有越权字段，按提示修 manual 后重跑；
- skillverify 加了**新命令**时，`git diff` 会看到新节点没有语义层数据——转 §四 补 manual。

## 三、MAINT-02：同步 manual 与指南（行为变更后）

**触发**：skillverify 行为变更（REV 规则/判定口径/schema 语义——REV 规则指语义评审提示词的行为与判据）——这类变更
机械层看不见，生成器不会报，只能人工对。

1. 对照操作手册.md（评测资产 A3–A4b、交付门禁 A6、语义评审 A5）与验证流程指南.md（五·语义评审 / 六·交付门禁）确认哪些 manual 条目要改；
2. 编辑 `console/manual/*.json`（每节点一文件；**保持 ref 溯源字段**指向指南章节；
   新节点必带七问字段：summary/execution/compose_rules/effects/inputs/outputs/consumers）;
3. 重跑 `python console/build.py` + 守卫；
4. **指南修订与 manual 更新放同一 commit**——两处说的是同一件事，分开提交必漂移。

## 四、MAINT-03：桥模式日常——处理"语义层待补"徽标

桥模式下每次刷新页面，`/catalog` 会**实时内省** skillverify 并与入库快照 diff：

- skillverify 新增了命令而 `console/manual/` 没有对应语义文件 →
  该节点挂**"语义层待补"徽标**，顶部横幅出现"新增节点 N"；
- **处理**：补 `console/manual/<命令>.json`（新域还要加 `_domain.<域>.json` 声明域/流程线）
  → **保存后刷新页面徽标即消，无需重建**（桥实时读 manual 目录）；
- **收尾**：桥模式页面用的是实况数据，但入库快照（nodes.json / index.html 内联）
  已滞后——仍要跑一次 `python console/build.py` + 守卫，让快照跟上并随 manual
  同 commit 提交，否则守卫测试会红；
- 参数变更（不是新命令）→ 横幅逐字段显示 `param_changes`，核对后同 §二 流程。

## 五、describe 契约（内省数据源，EVOL-01）

- 内省脚本 `introspect.py` 默认 `--data-source auto`：目标模块按 describe 协议
  导出 `describe_surface()`（skillverify 已提供，等价于 `skillverify describe --json`）
  就优先用它——稳定契约、不解析 argparse 私有结构；没有协议的工具自动回退遍历 parser；
- **两条数据源产出逐字段一致**（守卫第 5 断言把关）——切数据源对 nodes.json 零影响；
- `skillverify describe --json` 输出 schema `skillverify.describe/1`，字段语义变更
  必须升 schema 版本号——契约是对外承诺；
- 自定义 parser 接桥：`serve_bridge.py --import <模块> --factory <工厂> --extra-path <目录>`
  （该工具没有 describe 协议也没关系，argparse 兜底）。

## 六、排障 FAQ

**Q：页面打开后徽标灰色"静态模式"，没有"桥已连接"？**
桥没起来或端口不对。先看桥窗口是否存活、`netstat -ano | findstr 8742` 是否 LISTEN；
再刷新页面（探桥超时 1.5 秒）。桥启动即退出且报端口占用 → 有旧进程占着 8742：
`taskkill /PID <pid> /F` 后重跑 start.bat。

**Q：对 GET /catalog 全部 501 / 行为诡异？**
端口被旧进程"重复绑定"（Windows SO_REUSEADDR 陷阱）：`netstat -ano | findstr LISTEN`
看到同端口两行 LISTEN 即是，杀旧 PID。

**Q：start.bat 提示找不到 Python，但我明明装了？**
Python 没进 PATH：重开终端窗口（PATH 刷新）再跑；或你用的是 uv——脚本会自动
尝试 `uv run python`，uv 也不在 PATH 时先装 uv。**不要**把 Python 装到带空格/中文
的路径里。

**Q：`python -m skillverify` 报 No module named skillverify？**
你不在仓库根目录跑（start.bat 已自动处理，手动跑请先 cd 到仓库根）；或想用
全局安装版：`pip install skillverify`。

**Q：守卫测试红了？**
按 FAIL 行提示处理：nodes.json 与重生成不一致 → `python console/build.py` 后过目
diff 再提交；lint 规则对账红 → skillverify lint 源码加了规则，重跑生成器同步
`manual/lint.json`；describe 等价断言红 → skillverify 契约或内省映射被改动，跑
两条 `--data-source` 对比定位。

**Q：语义层待补的节点在页面上点不了/不可见？**
manual 只补了节点文件、没接进任何 pipeline——在 `_domain.<域>.json` 的 `nodes`
列表与某条 pipeline 的 `steps` 里加上它。
